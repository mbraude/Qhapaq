# Documentation Conventions

**Applies to:** Repository Markdown documentation, including `README.md`,
`**/README.md`, and `docs/**/*.md`.

These rules specialize the [common coding conventions](../coding-conventions.md)
for maintained documentation. Follow [AGENTS.md](../../../AGENTS.md) and the
applicable [product specifications](../../../specs/README.md). [SPEC-0008
R-0008-004](../../../specs/0008-multi-language-conformance-and-repository-organization.md#5-engineering-policy-ownership-and-applicability)
defines this guide's policy ownership.

## Authoring

- Write for the stated audience and help the reader complete a concrete task
  or understand a defined area.
- Link to specifications for normative behavior instead of copying rules that
  may drift.
- Clearly label planned or unavailable functionality.
- Use repository-relative links, descriptive headings, and descriptive link
  text.
- Add language identifiers to fenced code blocks.
- Keep examples synthetic and free of credentials, private endpoints, and
  sensitive payloads.
- Identify generated documentation and its authoritative source.
- Preserve accessibility through meaningful hierarchy, alt text, and simple
  table structure.

# SPEC-0006: Work Plan

## Scope and authority

This plan tracks the initial .NET layered architecture in
[SPEC-0006](../../specs/0006-dotnet-layered-architecture.md), including its
alignment with the portable implementation and repository migration work in
[SPEC-0007](../../specs/0007-portable-pipeline-definitions-and-binding.md)
and [SPEC-0008](../../specs/0008-multi-language-conformance-and-repository-organization.md).
It does not define product behavior, duplicate work owned by those plans, or
authorize implementation, source relocation, or Entry Point identity changes.

The current .NET solution and architecture tests are partial legacy scaffolding:
the Entry Point projects still use `Qhapaq.Implementations.*` identities.
Their matched identity migration and later source relocation are owned by
SPEC-0008. Existing architecture tests are baseline evidence, not completion of
the required checks.

## Phase 0: Reconcile the first Service V1 use-case record

### Entry gates

SPEC-0007 D-0007-004 resolves the first Service V1 use case and its exact public
contracts. SPEC-0006 R-0006-004, R-0006-005, and R-0006-033 remain authoritative.

### Ordered items

| Order | Item | Outcome |
| --- | --- | --- |
| 1 | [I-0006-001](implementation/I-0006-001-reconcile-service-v1-decision.md) | Align SPEC-0006's open-question and rollout references with the accepted SPEC-0007 decision |

### Exit gates

SPEC-0006 no longer presents resolved Service V1 choices as open; ownership and
requirement identifiers remain intact; no new behavior or API is introduced.

## Phase 1: Deliver and verify the initial layered architecture

### Entry gates

Approved readiness for the exact SPEC-0006 scope and approved implementation
slices. The initial architecture enforcement and descriptor-retrieval
implementation remain owned by SPEC-0007. Entry Point identity migration and
source relocation remain separately gated by SPEC-0008 R-0008-027 through
R-0008-029.

### Ordered items

| Order | Item | Outcome |
| --- | --- | --- |
| 1 | [I-0006-002](implementation/I-0006-002-initial-layered-architecture.md) | Verify the initial scaffold and first Service V1 vertical slice against SPEC-0006 |

### Exit gates

The initial project and test structure, adjacent-layer contracts and composition,
first real Service V1 flow, package-consumer boundaries, and architecture
enforcement satisfy the scoped SPEC-0006 requirements. Do not claim complete
SPEC-0006 conformance from this initial-slice gate; later SPEC-0007 capabilities
remain subject to their own architecture and conformance tests.

## External prerequisites

- [I-0007-001](../0007/implementation/I-0007-001-architecture-enforcement.md)
  owns architecture-test extensions for layer boundaries, model ownership,
  helper ownership, and representative relationships, including
  SPEC-0006 R-0006-020, R-0006-021, R-0006-024, and R-0006-030 through
  R-0006-041. Its exact implementation slices and readiness are not yet approved.
- [I-0007-011](../0007/implementation/I-0007-011-first-service-cli-slice.md)
  owns the first non-executing Service V1 and CLI vertical slice and its
  SPEC-0006 model-flow requirements. Its exact implementation slices and
  readiness are not yet approved.
- [I-0008-008](../0008/implementation/I-0008-008-entry-point-identity-migration.md)
  owns the separately gated Entry Point identity migration.
- [I-0008-004](../0008/implementation/I-0008-004-source-relocation.md)
  owns the later source relocation and path updates. Neither migration item is
  authorized by this plan.
- Further SPEC-0007 implementation items own the portable validation,
  descriptor-generation, registry, and execution architecture that realizes
  SPEC-0006 R-0006-039 through R-0006-041 and later model families. This plan
  does not copy those work items or make their outputs prerequisites for the
  first non-executing retrieval slice unless their owning plans require them.
